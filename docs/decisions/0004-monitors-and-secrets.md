# 0004 — Monitors, secrets and destination checks

**Status:** accepted · 2026-11-16

## Custom headers are write-only secrets
- Encrypted with **AES-256-GCM** (`ENCRYPTION_KEY`, 32 bytes) before they reach PostgreSQL.
  Envelope: `version | iv (12) | tag (16) | ciphertext`, fresh IV per write.
- The ciphertext is bound to its row with associated data `monitor-headers:<org_id>:<monitor_id>`:
  a value copied onto another monitor, or into another organization, fails to decrypt.
  The monitor id is generated by the application before insert so it can be part of the binding.
- Only header **names** are stored in clear (`header_names`) and returned by the API. Values are never
  returned; an update without `headers` keeps them, an update with `headers` replaces the whole set.
- Headers that would change routing or framing (`Host`, `Content-Length`, `Transfer-Encoding`,
  `Connection`, …) are refused, as are values containing CR/LF (header injection).

## Destination checks (SSRF), part 1
At creation and update, URLs are refused when they:
use a scheme other than http/https, embed credentials, name `localhost`, `*.local`, `*.internal`
or a single-label host, or are an IP literal in a private, loopback, link-local (cloud metadata
`169.254.169.254`), CGNAT, multicast, documentation or reserved range — including decimal, hex and
IPv4-mapped IPv6 spellings (`http://2130706433`, `http://0x7f.0.0.1`, `http://[::ffff:7f00:1]`).

This is **not** the protection: DNS can change after creation and redirects can point inward.
Phase 4 resolves the host at every check, validates each address with the same `isBlockedAddress`,
pins the connection to the validated IP and re-validates every redirect hop.

Implementation note: Node's `net.BlockList` treats a `::ffff:0:0/96` rule as matching **every**
IPv4 address, so IPv4-mapped addresses are unwrapped and judged as IPv4 instead. A unit test pins this.

## Lifecycle and invariants
- New and resumed monitors are due immediately (`next_check_at = now`); paused monitors have
  `enabled = false`, `state = 'paused'` and no `next_check_at` (a check constraint keeps these consistent).
- Changing the URL resets state and counters: earlier results described another endpoint.
- Cross-field rules (timeout below interval, status range order, keyword only with GET) are validated
  on the **merged** record for updates, and enforced again by database check constraints.
- At most 50 monitors per organization; creations are serialized per organization with an advisory lock so
  concurrent requests cannot overshoot the quota.

## Listing
Keyset pagination on `(created_at DESC, id DESC)` with an opaque cursor, backed by
`monitors_org_created_idx`. Search escapes `%`, `_` and `\` so user input is matched literally.
